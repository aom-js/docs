Здесь собираются **практические** ответы на вопрос «как правильно написать вот это» — с рабочими примерами, объяснением, почему именно так, и указанием, где тот же код исполняется тестом.

Чем это отличается от остальной документации:

| Файл                         | Что в нём                                                                |
| ---------------------------- | ------------------------------------------------------------------------ |
| страница пакета             | справочник: что делает каждый декоратор, какие поля у каждого класса     |
| [Архитектура ядра](../architecture.md)       | как устроено ядро целиком: пакеты, зависимости, фазы, порядок исполнения |
| **рецепты**                  | **как писать прикладной код и на чём тут спотыкаются**                   |

## Правила ведения

1. **Каждый пример исполняется тестом.** Рецепт без теста устаревает и начинает врать. В конце каждого рецепта — ссылка на тест-файлы, в которых лежит тот же код; в самом тесте — комментарий-обратная ссылка на рецепт.
2. **Сначала рабочий код, потом объяснение.** Рецепт читают, когда что-то не получается, а не для общего развития.
3. **Антипримеры обязательны.** Если приём не работает или работает не так, как кажется, — показать неверный вариант рядом с правильным.
4. **Никаких повторов справочника.** Список аргументов декоратора — в readme пакета; сюда попадает только то, что из сигнатуры не видно.
5. Один рецепт — один файл, имя по теме ([рецепт про `@This`](this-and-instances.md)), а не порядковое вроде «router-2».
